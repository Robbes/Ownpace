# ADR-0045: Migrations are hand-written SQL, applied by our own runner

- **Status:** Accepted
- **Date:** 2026-09-09
- **Deciders:** owner
- **Supersedes:** the authoring-and-applying half of [ADR-0017](./0017-migration-tooling.md); its Atlas lint, its data-migration properties and its rejection of Liquibase/Flyway all still stand.

## Operative rules

<!-- What holds NOW. Amend these bullets in place when a later decision changes them;

- Migrations are **hand-written numbered SQL files**, one per change: `packages/ledger/migrations` for the shared chain, `packages/managed/migrations` for the managed-only one (ADR-0036).
- **`runMigrations`** applies them at startup, linearly, under a Postgres advisory lock, recording each filename in `schema_migrations`; the appliance and the worker both call it. Nothing applies a migration by hand.
- **Drizzle Kit authors and applies nothing here.** `pnpm db:generate` and `pnpm db:migrate` refuse (`scripts/how-migrations-are-authored.mjs`), and `drizzle.config.ts` points its `out` at a throwaway directory so the tool cannot write into a chain. Drizzle the ORM is untouched, and `schema-matches-migrations.unit.test.ts` compares it against the chain on every run.
- Pre-release only, `scripts/squash-migrations.sh` folds the chain into `0001_baseline.sql` — by dumping an applied database, never by hand-merging SQL.
- Nothing may sort below a chain's baseline; `scripts/a-command-the-docs-told-you-to-run.unit.test.ts` enforces it, because the runner applies files in sorted order.

## Context

ADR-0017 chose Drizzle Kit in June 2026, before there was a chain to author. Its
operative rule read *"Drizzle Kit authors and applies migrations"*, and — because
ADR-0038 assembles operative rules into `OPERATIVE.md` — that sentence was a live
instruction to every reader, human and agent.

It was never true of this repository. The evidence is the chain itself, measured
2026-09-09:

- Every migration filename ever added to either chain is hand-authored and prose-named
  (`0023_the_tick_stops_reading_all_of_history.sql`), not a Drizzle random pair
  (`0002_lush_thunderbolt.sql`).
- **No `migrations/meta/_journal.json` has ever been tracked** — the file drizzle-kit's
  own runner reads to know what to apply. Without it, it has never had anything to apply.
- `0001_baseline.sql` is generated by `scripts/squash-migrations.sh` from a dump of an
  applied database, and the runner is `packages/ledger/src/migrate.ts`, keyed on
  `schema_migrations`, not drizzle-kit's `__drizzle_migrations`.

Left standing, the rule was worse than stale: it pointed at a command that damaged the
chain. `drizzle.config.ts` aimed drizzle-kit's `out` at the real migration directory, so
`pnpm db:generate` wrote a 30 KB `0000_*.sql` dump into it **and exited 0** — and `0000_`
sorts *below* `0001_baseline.sql`, which is the order `runMigrations` applies files in. The
error that would eventually surface named the baseline, a file nobody had touched.

## Decision

State what the repository does, and make the tooling agree with it.

Migrations are hand-written SQL. `runMigrations` applies them. Drizzle Kit is not part of
that path and the config can no longer reach it. Atlas continues to lint the chains in CI,
the data-migration properties (idempotent, batched, expand-contract) continue to hold, and
Liquibase/Flyway remain rejected for the reasons ADR-0017 gave — none of that depended on
who authors.

The owner's instruction, 2026-09-09, on being offered the choice between correcting
ADR-0017's bullet in place and superseding it:

> *"supersede it, since the ADR's need to reflect our decisions and may change over time."*

## Consequences

- The operative layer says what the repository does. An agent reading `OPERATIVE.md` is no
  longer told to run a command that breaks the build.
- Authoring a migration is a deliberate act — write the file — rather than a generated one.
  That is a cost, and it is the cost that produced prose-named migrations whose intent is
  legible years later.
- The Drizzle schema can still drift from the chain. That risk is unchanged and already
  covered: `schema-matches-migrations.unit.test.ts` compares them, per table and per
  column, both directions, on every test run.
- ADR-0017 keeps its title and its narrative. A reader who arrives at it finds a status
  line pointing here.

## Alternatives considered

- **Amend ADR-0017's bullet in place and leave the ADR otherwise as it was.** The
  convention allows it — ADR-0038 says operative bullets are amended in place. Rejected by
  the owner: an ADR whose title credits a tool it does not use misleads before anyone
  reaches the bullet.
- **Adopt drizzle-kit for real** — keep a `meta/` journal, generate migrations, apply with
  `drizzle-kit migrate`. Rejected: it would replace forty-one reviewed, prose-named files
  with generated ones, move bookkeeping to a second table, and give up the advisory lock
  and downgrade guard `migrate.ts` implements. The tool would be serving the ADR rather
  than the other way round.
